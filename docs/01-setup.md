# 1 — ArcGIS Pro setup

## Do this first: don't build from scratch

Almost everything visible on a standard IMT fire map ships out of the box in the
NWCG **GeoOps Incident Directory Structure**:

- Blank Event geodatabase — correct schema, correct domains
- `.lyrx` layer files carrying the current official symbology (point, line, polygon)
- `Event Group BAM Large Symbols.lyrx` — oversized symbols for the briefing map
- An ArcGIS Pro project template (`.aprx`) with a pre-built layout per map product
- A dynamic-text table so title, date and acreage populate themselves

Get it from the NWCG Geospatial Training Unit tools page —
<https://www.nwcg.gov/page/geospatial-training-unit-tools> — under "Current GSTOP /
GeoOps Folder Template". The folder structure item is also posted on NIFC AGOL.

Drawing your own icons is wasted effort and guarantees the products look
non-standard to anyone who has worked a real incident.

`scripts/make_folder_structure.py` builds a matching tree if you need one before
you have the template, but it cannot produce the geodatabase, the symbology or
the layouts. It is a fallback, not a substitute.

## Sequence

1. **Extract the GeoOps folder template** and rename it for the exercise.
   `2026_StormMountain` is the convention this repo assumes.

2. **Drop base data into `base_data/`** per [02-base-data.md](02-base-data.md).
   Clip and project on ingest, not later.

3. **Open the Pro project template.** Rename the databases, rename the map view,
   and set the map's coordinate system to **NAD 1983 UTM Zone 13N (EPSG:26913)**.
   Do this before you digitize anything — the acreage you calculate in a
   geographic CRS will be wrong and you will not notice until someone compares
   it to the 209.

4. **Save As** to your own edit project. Leave the template untouched so the next
   exercise starts clean.

5. **Load the blank Event GDB** — or build one with
   `scripts/arcpy/build_event_gdb.py`. Do **not** connect a training exercise to
   the live National Incident Feature Service. See
   [07-guardrails.md](07-guardrails.md).

6. **Repair the Event `.lyrx` paths** to your local Event GDB. This is the step
   people skip. Without it the symbology and the feature templates do not come
   through, and you end up hand-styling features one at a time.

7. **Digitize the incident**, or load the supplied mock incident:

   ```
   python scripts/arcpy/build_event_gdb.py --dest <incident>/incident_data
   python scripts/arcpy/load_mock_incident.py --gdb <incident>/incident_data/event.gdb
   ```

8. **Build one layout per product** from the provided templates. Same layer set
   every time — the products differ by definition query, not by layer list.

9. **Apply the definition queries** from `config/map_products.yml`. This is how
   the public product loses its tactical data, so it is not a cosmetic step.

10. **Export geospatial PDFs**:

    ```
    python scripts/arcpy/export_products.py --aprx projects/StormMountain.aprx --out products/pdf
    ```

    Georeferenced PDFs open in Avenza on a crew phone and show the holder's own
    position. That is worth teaching on its own and it costs one checkbox.

## Coordinate system, stated once

| | |
|---|---|
| Map view, analysis, layouts | NAD 1983 UTM Zone 13N — **EPSG:26913** |
| Graticule, coordinate tables | NAD 1983 geographic — EPSG:4269 |
| Datum statement on every sheet | `North American 1983 Datum. Lat/Long Grid` |

The AOI extent in both systems is in `config/aoi.json`, generated by
`scripts/make_aoi.py`. Read it from there rather than retyping corner
coordinates.

## Python environment

The pure-Python scripts (`make_aoi.py`, `make_mock_incident.py`,
`validate_event_data.py`, `make_coordinate_table.py`, `make_folder_structure.py`)
run on any Python 3.9+ with no third-party packages. Run them anywhere.

The scripts under `scripts/arcpy/` need `arcpy` and must be run with the ArcGIS
Pro Python:

```
"C:\Program Files\ArcGIS\Pro\bin\Python\envs\arcgispro-py3\python.exe" scripts\arcpy\build_event_gdb.py --help
```

`export_products.py` additionally needs `pyyaml`, which means cloning the
`arcgispro-py3` environment and installing into the clone. `derive_terrain.py`
needs a Spatial Analyst licence.
